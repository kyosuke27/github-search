# UI CSS 仕様書

## 目的

現在の機能とHTML構造を維持したまま、画面の見た目だけを整える。データ取得、イベント処理、API呼び出し、表示内容の意味は変更しない。

## 対象範囲

- `index.html` に読み込むCSSファイルの追加
- ページ全体、検索操作エリア、結果表示エリアのレイアウトと装飾
- ユーザー情報とリポジトリ一覧のカード表示
- ボタン、入力欄、セレクトボックスの通常時・ホバー時・フォーカス時のスタイル
- 画面幅に応じたレイアウト調整

## 対象外

- JavaScriptの処理変更
- GitHub APIの呼び出し方法や取得データの変更
- 新しい検索機能、ページング、ソート機能の追加
- 既存の表示項目やボタンの役割変更
- 外部CSSフレームワークの導入

## UI方針

- GitHubを連想できる、白を基調にしたシンプルな配色にする。
- コンテンツの最大幅を設定し、画面中央に配置する。
- 操作エリアと結果エリアを視覚的に分ける。
- 余白、文字サイズ、行間を統一して読みやすくする。
- 角丸と控えめな影を使い、情報のまとまりをカードとして表現する。
- 装飾よりもユーザー名入力と結果の確認を優先する。

## スタイル要件

### ページ

- `body` はデフォルトの余白をリセットし、読みやすいシステムフォントを使用する。
- メインコンテンツは左右の余白を確保し、最大幅を設定する。
- 背景色と文字色のコントラストを十分に確保する。

### 操作エリア

- 見出し、セレクトボックス、入力欄、ボタンをまとまりとして配置する。
- 入力欄とセレクトボックスは同じ高さにそろえる。
- ボタンは操作対象であることが分かる色とカーソルを設定する。
- `:focus-visible` でキーボード操作時のフォーカスを確認できるようにする。

### 結果エリア

- 結果が空の場合でも不自然な余白にならないようにする。
- ユーザー情報はアバターと基本情報を見やすく配置する。
- リポジトリ一覧は各リポジトリを区切って表示する。
- リポジトリ名のリンクはクリック可能であることが分かるようにする。
- 長い説明文やURLでレイアウトが崩れないようにする。

### レスポンシブ対応

- スマートフォン幅では操作項目を縦に並べる。
- デスクトップ幅では横方向の余白を広く取り、結果を読みやすくする。
- 横スクロールを発生させない。

## アクセシビリティ

- 通常文字と背景のコントラストを確保する。
- キーボードだけで入力、選択、ボタン操作ができる状態を維持する。
- フォーカス表示を消さない。
- リンク、ボタン、入力欄の状態を色だけに依存して表現しない。

## 完了条件

- JavaScriptの機能が変更前と同じように動作する。
- 操作エリアと結果エリアの区別が明確である。
- PCとスマートフォンの両方で横スクロールが発生しない。
- キーボード操作時にフォーカス位置を確認できる。
- 既存の表示内容とAPI連携に変更がない。
